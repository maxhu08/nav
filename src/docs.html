rules.urls.mode

Choose where nav actions are allowed. Only the selected list is used; the other list is ignored.

blacklist: Actions are allowed on all websites by default. Use `rules.urls.blacklist` to block sites or restrict their actions.

whitelist: Actions are blocked on all websites by default. Use `rules.urls.whitelist` to allow sites or specific actions.

rules.urls.blacklist / rules.urls.whitelist

Each rule starts with * <regex-pattern> on its own line. The pattern is a regular expression matched against the full page URL, not just the domain.

To block or allow an entire site, use only the pattern line. No `+` or `-` line is needed.

In blacklist mode, a pattern line alone blocks all actions on matching URLs. In whitelist mode, it allows all actions on matching URLs.

Add + action1 action2 below a pattern to allow only the listed actions and block all others.

Add - action1 action2 below a pattern to block only the listed actions and allow all others.

The first matching rule wins. Put more specific patterns before broader ones.

Optional action lines behave the same in both modes. Put a single `+` or `-` line immediately below its pattern, with no blank line or comment between them.

A `+` or `-` line must contain at least one valid action name. Separate action names with spaces. A standalone `+` or `-` is not valid.

Start pattern and action lines at the beginning of the line, without indentation. Blank lines and lines starting with `#` are ignored.


Example: allow all actions only on github.com and example.com

Select whitelist mode and paste this into `rules.urls.whitelist`:

* ^https?://([a-z0-9-]+\.)*github\.com/
              * ^https?://([a-z0-9-]+\.)*example\.com/

All nav actions are allowed on these sites, including their subdomains. All actions remain blocked on other sites.


Example: block all actions on github.com

Select blacklist mode and paste this into `rules.urls.blacklist`:

* ^https?://([a-z0-9-]+\.)*github\.com/

All nav actions are blocked on GitHub and its subdomains. Other sites remain allowed.


Example: allow only specific actions on github.com

* ^https?://([a-z0-9-]+\.)*github\.com/
              + hint-mode-current-tab
                hint-mode-right-click yank-current-tab-url

In either mode, this allows only the three listed actions on GitHub. Other sites follow the selected mode's default: allowed in blacklist mode, blocked in whitelist mode.


Example: block only specific actions on github.com

* ^https?://([a-z0-9-]+\.)*github\.com/
              - scroll-down scroll-up

In either mode, this blocks `scroll-down` and `scroll-up` on GitHub and allows every other action there. Other sites still follow the selected mode's default.

hotkeys

hotkeys.mappings

Each line maps one key sequence to one action name.

<key-sequence> <action-name>

Put one mapping on each line.

Modifier keys are specified as `<c-x>`, `<m-x>`, and `<a-x>` for `ctrl+x`, `meta+x`, and `alt+x`. Combined modifiers are written like `<c-a-x>` or `<c-m-x>`. Use `<space>` for the space key.

Reserved config characters must use named tokens:
- `<` is `<chevronleft>`
- `>` is `<chevronright>`
- `#` is `<hashtag>`

Actions run in mode context:
- Normal mode actions work in regular browsing mode.
- Find mode actions (`cycle-match-next`, `cycle-match-prev`) only work while find mode is active.
- Watch mode actions (`toggle-fullscreen`, `toggle-play-pause`) only work while watch mode is active.
- Visual actions share one keymap across caret, visual, and visual-line modes. Normal-mode actions do not fall through while selecting text.
- Escape and Ctrl-[ leave typing in editable fields. These keys are fixed; ordinary typing is never buffered.

Default hint bindings are `f`, `F`, and `<a-f>` for current-tab, new-tab, and right-click hint mode.

Right-click hint mode behaves like current-tab hint mode, except it right-clicks the selected target, ignores reserved directives, and always shows the cursor marker.

A key sequence can be reused across different modes (for example `f` for hints in normal mode and fullscreen in watch mode), but duplicate mappings in the same mode are rejected.

Lines starting with # are ignored.

Action syntax highlighting:
- Normal mode actions are yellow.
- Find mode actions are orange.
- Watch mode actions are green.
- Visual mode actions are purple.
- Invalid tokens are red.

In normal mode:

visual-mode / visual-line-mode / visual-restore

Defaults: `v`, `V`, and `gv`. Enter characterwise or whole-rendered-line selection, or restore the last visual selection on this page. Without a usable selection, entry falls back to caret mode: move to a starting point, then press `v` or `V`. Automatic placement prefers substantial visible text and falls back to short text on sparse pages. Restore refuses changed text/endpoints or a changed page URL. Existing configs receive these entry actions as `<unbound>`, with the mode-local bindings populated automatically.

In caret, visual, and visual-line modes:

In Chromium, leave typing with Escape or Ctrl-[, then press `v` or `V` to select inside that same input or textarea. Clicking elsewhere or changing the field invalidates the saved selection. Mode changes show a brief toast instead of a persistent overlay.

The same keys move a one-character caret, extend a characterwise selection, or extend whole rendered lines. These are text-selection modes, not editors. Keys typed in inputs and contenteditable fields remain native until a selection mode is active. Editable-field movement depends on browser support; Firefox does not move input/textarea selections through the native selection API.

`visual-left/right/down/up`: `h/l/j/k` and arrows. `visual-word-forward/backward/end`: `w/b/e`; `W/B` alias `w/b`. `visual-line-start/end`: `0/$`. `visual-document-start/end`: `gg/G`. `visual-sentence-forward/backward`: `)/(`. `visual-paragraph-forward/backward`: `}/{`. Counts such as `3w` repeat movement. Sentence/paragraph fallbacks in Firefox are approximate.

`visual-select-word/sentence`: `aw/as`, select the current word or sentence. `visual-select-inner-word`: `iw`, the current word or punctuation/whitespace run without surrounding whitespace; counts include separators between words. `visual-reverse`: `o`, swap which endpoint moves.

`visual-character`: `v`, characterwise selection. `visual-line`: `V`, whole rendered lines. `visual-caret`: `c`, collapse to a one-character caret. Escape (or `Ctrl-[`) clears pending input first, otherwise exits. Escape normally collapses to the moving endpoint, other exits to the anchor; selections present on initial user entry are retained. Clicking a focusable element also exits.

`visual-yank`: `y` or unmodified Enter, copy and exit. `visual-yank-line`: `Y`, select and copy line(s), including a following newline. `visual-open-current-tab/new-tab`: `p/P`, copy and open a URL or search the selected text using your configured search engine.

`visual-find`: `/`, open find and return to visual mode when finished; cancel restores the previous selection. `visual-find-next/prev`: `n/N`, select another match instead of extending to it. `visual-scroll-down/up`: `Ctrl-e/Ctrl-y`, scroll without moving the selection.

hints

hints.showCapitalizedLetters

Changes how hint labels are displayed. The required key presses stay lowercase.

hints.improveThumbnailMarkers

Makes hint markers much easier to see on thumbnail-like media targets by centering them and rendering a larger badge.

hints.activationIndicator.enabled

Shows a temporary activation ring after you open or focus something through hints.

hints.activationIndicator.color

Sets the activation ring color used when `hints.activationIndicator.enabled` is on.

hints.charset

Controls which letters are used to generate hint labels. Letters earlier in the charset are prioritized first.

This applies to generated (non-reserved) hint labels. Reserved directive labels can still be typed even if they use letters outside this charset.

Use letters only, with no spaces and no duplicates. Any repeated character, whitespace, or non-letter is treated as an error.

hints.minLabelLength

Sets the minimum number of characters generated hint labels must use.

hints.avoidAdjacentPairs

Lists consecutive character pairs to avoid inside generated hint labels. It is recommended to put hard-to-press character pairs here.

Separate pairs with spaces or newlines. Entries must be exactly two letters, and `#` starts a comment anywhere on the line.

hints.directives

Sets preferred hint directives for special elements.

Rules:
- Each directive must be on its own line.
- Use exactly one space between the directive and labels, and between labels.
- Labels must contain only letters a-z and each next label must be exactly one character longer than the previous label.
- Matching directive hints show the directive icon next to the hint label.
- Directives can use letters outside `hints.charset` and are still typeable in hint mode.

hints.advanced.customSelectors

Adds site-specific selector overrides for hint generation.

This option can override the default hint target discovery on sites where important interactive surfaces are not exposed as normal clickable HTML controls.

It is especially useful for applications with custom chat inputs, editors, or button-like surfaces that rely on framework-managed click handling instead of standard browser semantics.

Matching selectors allow nav to surface those targets in hint mode so they can still be addressed and activated with a click event.

Rules:
- Each site block must start with `* <regex-pattern> {` and end with `}`.
- `regex-pattern` matches `window.location.href`.
- Each entry inside the block must be `<key> <css-selector>`.
- `key` must be letters only and at least as long as `hints.minLabelLength`, or exactly `<auto>`.
- `<auto>` keeps the selector site-specific but lets the label be generated from `hints.charset`.
- Explicit keys reserve that label and override the normal generated label for the first visible matching element.
- Custom selector matches are included in hint generation even when the page would not normally expose them as hintable targets.

* ^https://chatgpt\.com/ {

  proj button[data-testid='create-new-project-button']

  <auto> nav[aria-label='Chat history'] a

}

bar

bar.styling

Choose `default` for the built-in appearance or `custom` to use `bar.customCSS`. Switching back to default preserves your custom CSS. Save to apply changes to open pages.

bar.customCSS

Replaces the Bar appearance while retaining its essential layout and interaction rules. The editor starts with the built-in stylesheet. CSS is scoped to Bar mode, including URL/search prompts, tab search, and suggestions, inside the isolated UI. Custom prompt themes use CSS `@scope`, supported by Chrome 118+ and Firefox 146+.

Use `:scope` for the prompt, `#nav-find-input` for its input, `.nav-find-suggestion` for suggestion rows, and `.nav-find-suggestion[data-selected="true"]` for the selected suggestion. Use `:scope[data-prompt-kind="tabs"]` to target tab search separately. Media queries and pseudo-classes work normally within the scope.

The starter CSS uses `--nav-prompt-color`, `--nav-prompt-width`, and `--nav-prompt-text-size` so the existing controls remain active. Dimensions are provided in pixels; `--nav-prompt-font-scale` preserves responsive text sizing. Explicit CSS values override these variables. An empty custom stylesheet removes the visual theme rather than restoring the default.

bar.width

Unitless width for the URL/search and tab-search bars. Each unit is 16px, capped to fit the viewport.

bar.textSize

Unitless text size for the bar and its suggestions. Uses responsive scaling: value × 16px × 0.4 below 768px, × 0.75 from 768px, and × 1 from 1024px. Internal pixel sizing keeps the result independent of a site's root font size.

bar.color

Sets the outline color of the bar prompt UI.

bar.tabsColor

Sets the outline color of the tab search bar. Defaults to Tailwind sky-500 (#0ea5e9).

bar.searchEngineURL

Used when bar input is treated as a search instead of a URL.

Use `{}` to represent the search query.
Example: `https://www.google.com/search?q={}`.

bar.search.suggestions

Shows live query suggestions as you type.

Suggestions are sourced from DuckDuckGo's public autocomplete suggestions API and are not based on your personal search history. Requests are sent directly from your browser to DuckDuckGo and do not include cookies, accounts, extension identifiers, or other personal data.

bar.search.history

Shows matches from your local browser history for past searches and visited links.

History lookups stay on-device and are not sent to us or any third party.

bar.search.tabs

Shows matching open tabs in the normal bar. Selecting a tab activates it and focuses its window instead of opening a duplicate. Lookups stay on-device.

bar.search.bookmarks

Shows matches from a configurable bookmark list that you manage locally.

bar.search.bookmarks.storage

Stores the bookmark entries used when `bar.search.bookmarks` is enabled. Use one bookmark per line in the format `"bookmark name": "value"`.

find

find.styling

Choose `default` for the built-in appearance or `custom` to use `find.customCSS`. Switching back to default preserves your custom CSS.

find.customCSS

Replaces the Find appearance independently of Bar mode. Use `:scope` for both the prompt and next/previous widget, `:scope#nav-find-bar` for just the prompt, or `:scope#nav-find-status` for just the widget. The widget keeps its Find styling even while a Bar prompt is open. As with Bar, the starter CSS uses the existing appearance controls through CSS variables.

Set `--nav-find-match-background`, `--nav-find-current-match-background`, and `--nav-find-match-color` on `:scope` to change normal-match backgrounds, the current-match background, and match text. These values are read from the next/previous widget when settings are applied, so set them on `:scope` or `:scope#nav-find-status`, not only on the prompt. Invalid colors fall back to the built-in match colors. Only resolved colors are applied to the webpage; the custom stylesheet itself stays inside the UI. 

            /* Add after the starter CSS. */
            :scope {
            background: #202430;
            border-radius: 12px;
            --nav-find-match-background: #554400;
            --nav-find-current-match-background: #ffcc00;
            --nav-find-match-color: #ffffff;
            }

find.width

Unitless width of the find bar. Each unit is 16px, capped to fit the viewport. Does not change the next/previous match widget.

find.textSize

Unitless text size of the find bar. Uses the same responsive scaling as bar.textSize. Does not change page text or the next/previous match widget.

find.color

Sets the outline color for the find bar and the next/prev widget.
